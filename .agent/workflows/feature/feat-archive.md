Archive a completed feature change, extending the standard opsx-archive process with code-documentation synchronization and preservation of feat-apply tracking artifacts.

**Input**: Optionally specify a change name (e.g., `/feat-archive add-auth`). If omitted, check if it can be inferred from conversation context. If vague or ambiguous you MUST prompt for available changes.

**Steps**

1. **Invoke feat-archive skill**
   Read and rigorously follow the instructions in `.agent/skills/feat-archive/SKILL.md`.

This skill performs the standard archive flow (identify change, check completion, sync specs, archive), but with two major extensions:

**A. Code-vs-Documentation Sync Check**
Before archiving, compare actual source code changes against the change's documentation artifacts (proposal, design, specs):
- **If MATCH**: Display confirmation message "[OK] Documentation is in sync with source code"
- **If MISMATCH**: Auto-edit the documentation to match the actual implementation, add `> [!WARNING]` markers in corrected sections, and display a detailed mismatch report

**B. Tracking Artifact Preservation**
Ensure all tracking artifacts generated by `feat-apply` are included in the archive:
- `todo-uncover.md` — TODOs and edge cases discovered during implementation
- `new-apis.md` — New API endpoints documentation
- `delta-spec.md` — Impact scope and behavioral deltas

These files travel with the change directory during the archive move.

**Guardrails**
- MUST perform code-vs-documentation sync check before archiving
- MUST only edit documentation to match code — never edit code to match documentation
- MUST add `> [!WARNING]` markers when auto-correcting documentation
- Do NOT block archive on warnings — inform, confirm, and proceed
- Do NOT auto-select a change — always let the user confirm
